# آزمایشگاه بینایی ماشین VisionLab

**VisionLab** یک پروژه عملی و تحقیقاتی در حوزه بینایی ماشین و تشخیص اشیا (Object Detection) است. این پروژه مسیر کامل کار با یک مدل یادگیری عمیق را پوشش می‌دهد: آماده‌سازی داده، آموزش و ارزیابی، آزمایش‌های بهینه‌سازی، تبدیل مدل به ONNX و اجرای آن در Python، برنامه C#/.NET و مرورگر.

> **دموی آنلاین:** [majidabbasii.github.io/VisionLab](https://majidabbasii.github.io/VisionLab/) · **راهنمای انگلیسی:** [README.md](README.md) · **کارت مدل:** [model-card.html](model-card.html)

## قابلیت‌های دموی وب

مدل YOLO11n در مرورگر و با ONNX Runtime Web اجرا می‌شود. برای استفاده، ابتدا `Load model` را بزنید و پس از آماده شدن مدل، یکی از ورودی‌ها را انتخاب کنید.

### ۱. تشخیص تصویر

- انتخاب تصویر JPG، PNG یا WEBP یا کشیدن و رها کردن فایل در صفحه
- نمایش Bounding Box، نام کلاس و امتیاز Confidence
- تنظیم آستانه Confidence و آستانه IoU برای Non-Maximum Suppression (NMS)
- نمایش تعداد تشخیص‌ها و جزئیات هر شیء

### ۲. پردازش فایل ویدیو

- انتخاب فایل ویدیویی MP4، WEBM یا OGG
- محدودیت فایل ویدیو: حداکثر ۱۰۰ مگابایت و ۵ دقیقه
- پردازش فریم‌های ویدیو با همان مدل ONNX در مرورگر
- نمایش کادرها و برچسب‌های تشخیص روی فریم‌ها
- توقف پردازش و دریافت ویدیوی پردازش‌شده با فرمت WEBM، در مرورگرهای پشتیبانی‌کننده از `MediaRecorder`

توجه: خروجی ویدیوی پردازش‌شده از Canvas ضبط می‌شود؛ صدای فایل ورودی در خروجی ترکیب نمی‌شود. در طول پردازش ممکن است برای حفظ سرعت، همه فریم‌های ویدیوی اصلی پردازش نشوند.

### ۳. تشخیص زنده با وب‌کم

- درخواست دسترسی دوربین از مرورگر
- پردازش فریم‌های دوربین و نمایش تشخیص‌ها به‌صورت زنده
- توقف دوربین و آزادسازی MediaStream

برای دسترسی به دوربین، سایت باید روی HTTPS یا `localhost` اجرا شود و کاربر مجوز دوربین را بدهد. عملکرد و نرخ فریم به دستگاه، مرورگر، دوربین و بار پردازشی بستگی دارد.

### ۴. تحلیل نتایج

پنل Analytics پس از اجرای تصویر، ویدیو یا وب‌کم اطلاعاتی از جمله تعداد اشیای فریم اخیر، تعداد کلاس‌های متمایز، میانگین Confidence، زمان اجرای Inference، نرخ پردازش و توزیع کلاس‌ها را نمایش می‌دهد. نرخ FPS در این ابزار نرخ پردازش مشاهده‌شده است و معادل تضمین نرخ فریم دوربین یا ویدیوی ورودی نیست.

## حریم خصوصی و نحوه اجرا

- پیش‌پردازش و استنتاج مدل در مرورگر و روی دستگاه بازدیدکننده انجام می‌شود.
- تصویر، فریم‌های ویدیو و فریم‌های دوربین به سرور VisionLab ارسال نمی‌شوند.
- فایل مدل ONNX و فایل نام کلاس‌ها از سایت دریافت می‌شوند.
- کتابخانه ONNX Runtime Web و فایل‌های WebAssembly از CDN جاوااسکریپت jsDelivr بارگیری می‌شوند.
- Execution Provider فعلی در وب، WebAssembly CPU است؛ WebGPU فعال نشده است.
- برای ضبط خروجی ویدیو، پشتیبانی مرورگر از Canvas `captureStream` و `MediaRecorder` لازم است.

## مدل و مشخصات فنی

| مشخصه | مقدار |
|---|---|
| معماری | Ultralytics YOLO11n |
| وظیفه | تشخیص اشیا (Object Detection) |
| دسته‌ها | ۸۰ کلاس COCO |
| اندازه ورودی | `1 × 3 × 640 × 640` |
| اندازه خروجی خام | `1 × 84 × 8400` |
| فرمت | ONNX، Opset 17 |
| حجم مدل وب | حدود ۱۰٫۷ مگابایت |
| Runtime وب | ONNX Runtime Web 1.23.2 |
| Execution Provider وب | WebAssembly CPU |

مدل شامل ۸۰ دسته مانند انسان، خودرو، اتوبوس، دوچرخه، حیوانات، خوراکی‌ها، مبلمان و وسایل الکترونیکی است. این مدل اشیای دلخواه خارج از این دسته‌ها را به‌طور عمومی تشخیص نمی‌دهد.

## معماری کلی پروژه

پروژه سه مسیر اجرای اصلی دارد:

1. **Python:** پژوهش، آموزش YOLO11، ارزیابی، Export و آزمایش‌ها با Ultralytics و PyTorch.
2. **C# / .NET 8:** اجرای مدل ONNX با ONNX Runtime و OpenCvSharp؛ شامل تصویر، پردازش پوشه، فایل ویدیو و وب‌کم.
3. **مرورگر:** اجرای همان مدل ONNX با JavaScript و ONNX Runtime Web؛ شامل تصویر، ویدیو، وب‌کم و پنل Analytics.

مدل مشترک ONNX باعث می‌شود مسیر استنتاج در محیط‌های مختلف قابل مقایسه باشد.

## آموزش و آزمایش‌های تحقیقاتی

- آموزش و Fine-tuning مدل YOLO11n روی داده‌های مشتق‌شده از COCO
- ارزیابی با Precision، Recall، mAP50 و mAP50-95
- جست‌وجوی اکتشافی ابرپارامترها با Optuna
- تحلیل حساسیت آستانه Confidence، آستانه NMS IoU و اندازه ورودی
- Ablation Study برای مقایسه تنظیمات مختلف Data Augmentation
- خروجی ONNX و مقایسه نتایج Python و C#

### داده‌ها و نتایج ثبت‌شده

در آزمایش مجموعه داده توسعه‌یافته، تقسیم‌بندی ثبت‌شده شامل ۲۰٬۰۰۰ تصویر آموزش، ۵٬۰۰۰ تصویر اعتبارسنجی و ۵٬۰۰۰ تصویر آزمون بوده است. آموزش برنامه‌ریزی‌شده ۱۰۰ دوره‌ای به درخواست کاربر در دوره ۱۰ متوقف شد؛ بهترین Checkpoint انتخاب‌شده از دوره اول است. بنابراین نباید این اجرا را آموزش کامل ۱۰۰ دوره‌ای معرفی کرد.

نتایج ثبت‌شده روی مجموعه آزمون ۵٬۰۰۰ تصویری:

| معیار | مقدار |
|---|---:|
| Precision | 0.48972 |
| Recall | 0.35184 |
| mAP50 | 0.34698 |
| mAP50-95 | 0.22623 |

این اعداد مربوط به یک آزمایش و یک تقسیم‌بندی COCO هستند و تضمین عملکرد روی تصاویر واقعی یا دامنه‌های دیگر نیستند.

### تطبیق Python و C#

در آزمایش تطبیق ONNX روی ۱۰ تصویر، هر دو Runtime تعداد ۳۱ تشخیص تولید کردند و ۳۱ مورد از ۳۱ مورد با هم تطبیق داشتند. میانگین IoU جعبه‌های تطبیق‌یافته 0.97591 بود. این نتیجه شواهد خوبی برای هماهنگی دو مسیر در نمونه آزمایش‌شده است، اما تضمین تطبیق برای همه تصاویر و تنظیمات نیست.

### تست‌های خودکار ثبت‌شده

- Python: تعداد ۱۸ تست موفق
- .NET: تعداد ۹ تست Integration موفق
- ساخت Release برنامه .NET: بدون Warning و Error در گزارش ثبت‌شده
- تست C# روی هفت اندازه/حالت تصویر: هفت مورد با خروجی JSON معتبر
- تست ویدیوی C#: پردازش ۶۰ فریم در تست اخیر

## اجرای محلی دموی وب

از ریشه مخزن اجرا کنید:

```powershell
py -m http.server 8080 --directory docs
```

سپس آدرس `http://localhost:8080` را در مرورگر باز کنید. فایل HTML را مستقیماً با `file://` باز نکنید؛ بارگذاری مدل و فایل‌های Runtime به HTTP یا HTTPS نیاز دارد.

برای تست وب‌کم، `localhost` یک مبدأ امن محسوب می‌شود و مرورگر درخواست مجوز دوربین می‌دهد.

## محدودیت‌ها و موارد خارج از محدوده

- مدل فعلی یک مدل ۸۰ کلاسه COCO است؛ مدل Open-Vocabulary نیست.
- Object Tracking، Segmentation و Pose Estimation پیاده‌سازی نشده‌اند.
- اجرای وب از WebAssembly CPU استفاده می‌کند؛ WebGPU فعال یا بنچمارک نشده است.
- سرعت پردازش ویدیو و وب‌کم به سخت‌افزار و مرورگر بستگی دارد.
- برای جلوگیری از مصرف بیش از حد منابع مرورگر، فایل ویدیو به ۱۰۰ مگابایت و ۵ دقیقه محدود شده است.
- در ضبط WEBM خروجی، صدای ویدیوی ورودی منتقل نمی‌شود.
- پردازش فریم‌ها ممکن است از نرخ فریم اصلی ویدیو عقب بماند؛ همه فریم‌ها الزاماً پردازش نمی‌شوند.
- خروجی تشخیص برای کاربردهای پزشکی، ایمنی‌حیاتی یا تصمیم‌گیری‌های حساس طراحی نشده است.
- آموزش ۱۰۰ دوره‌ای مجموعه داده توسعه‌یافته کامل نشده است.

## انتشار در GitHub Pages

در مخزن GitHub از مسیر **Settings → Pages → Build and deployment** گزینه **Deploy from a branch** را انتخاب کنید، شاخه انتشار را روی شاخه اصلی مورد استفاده مخزن و پوشه را روی `/docs` قرار دهید. پس از موفقیت Workflow انتشار، نشانی سایت در تنظیمات Pages نمایش داده می‌شود.

## مجوز و حقوق داده‌ها

کد اصلی پروژه تحت GNU AGPL-3.0-only ارائه شده است. مدل‌ها، وزن‌های Ultralytics، وابستگی‌ها و داده‌های COCO ممکن است شرایط مجوز و انتساب جداگانه داشته باشند. مجوز کد پروژه به‌تنهایی حقوق تصاویر یا تمام اجزای شخص ثالث را پوشش نمی‌دهد.

مخزن و سایت شامل تصاویر COCO یا فایل کامل Annotationها نیستند. مجوز و حقوق عکس‌های منبع باید جداگانه بررسی شود. پیش از بازتوزیع وزن‌ها، مدل ONNX یا بسته‌های اجرایی، اطلاعیه‌های شخص ثالث و الزامات Corresponding Source در AGPL را بررسی کنید. این توضیحات مشاوره حقوقی نیستند.
